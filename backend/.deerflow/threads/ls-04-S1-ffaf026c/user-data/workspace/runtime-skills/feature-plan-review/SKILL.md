# 功能方案评审技能

当用户提供功能方案草稿并要求按照固定六步流程进行评审时，立即使用本技能。

## 工作流程

1. **读取输入**：获取用户提供的功能方案草稿文本。

2. **执行六步评审**：
   - **需求摘要**：用一句话概括核心需求，明确要解决的主要问题。
   - **用户价值**：分析功能对用户的核心价值、使用场景、目标用户群体和预期效果。
   - **功能拆解**：将需求拆解为具体功能模块和子功能，明确技术实现要点。
   - **实施风险**：识别技术、资源、时间、依赖、合规等方面的潜在风险。
   - **MVP范围**：定义最小可行产品范围，建议优先级和迭代计划。
   - **给研发的落地建议**：提供技术选型、架构设计、数据库设计、API接口、测试策略等具体建议。

3. **输出结构化报告**：按照上述六个部分输出清晰、可执行的评审报告。

## 使用场景

- 产品经理提交的功能方案草稿
- 技术方案初步评审
- 需求澄清和范围定义
- MVP范围规划
- 研发落地指导

## 注意事项

- 确保每个部分都基于输入内容进行具体分析，避免泛泛而谈。
- 风险识别要具体，包括技术可行性、资源需求、时间约束等。
- MVP范围建议应切实可行，聚焦核心价值。
- 落地建议要针对具体技术实现，避免空泛建议。
