# 产品需求分析

## 触发条件
当用户提供产品需求描述文本并要求按固定六步流程分析时，立即使用本技能。

## 输入
- 产品需求描述文本（通常为一段或多段文字）

## 输出
结构化分析报告，包含以下六个固定部分：

1. **一句话总结**
   - 用一句话概括该需求的核心目标

2. **核心用户问题**
   - 分析该需求要解决的用户痛点或业务问题
   - 明确目标用户群体

3. **关键功能点**
   - 列出实现该需求必须包含的核心功能模块
   - 按优先级或逻辑顺序排列

4. **边界与风险**
   - 识别功能边界（什么不做）
   - 分析技术风险、业务风险、实施风险

5. **MVP 建议**
   - 提出最小可行产品版本的建议范围
   - 说明优先级划分逻辑

6. **给研发的实现提示**
   - 提供技术实现的关键注意事项
   - 建议技术选型或架构思路

## 工作流程
1. 读取用户提供的产品需求文本
2. 按照上述六个部分进行结构化分析
3. 每个部分输出清晰、简洁的分析内容
4. 确保分析基于需求文本，避免过度假设
5. 输出完整的结构化报告

## 使用示例
**用户输入：**
"我们准备做一个面向零售门店总部的营销活动配置后台，支持按门店分组、用户等级和活动周期设置投放规则。"

**技能输出：**
### 1. 一句话总结
构建面向零售门店总部的营销活动配置后台，实现按门店分组、用户等级和活动周期的精细化投放规则设置。

### 2. 核心用户问题
- **用户痛点**：零售企业总部需要统一管理多门店营销活动，但缺乏标准化、可配置的投放规则管理工具
- **目标用户**：零售企业总部营销运营人员、区域经理、IT管理员
- **业务问题**：营销活动投放粗放，无法根据不同门店特性、用户等级和时间周期进行差异化配置

### 3. 关键功能点
1. **门店分组管理**：支持按地理位置、规模、类型等多维度创建和管理门店分组
2. **用户等级体系**：定义和维护用户等级规则（如普通会员、银卡会员、金卡会员）
3. **活动周期配置**：设置活动起止时间、重复规则、生效时段等时间维度配置
4. **投放规则引擎**：基于门店分组、用户等级、活动周期的组合条件配置投放规则
5. **配置预览与验证**：实时预览规则生效范围，验证规则冲突
6. **权限管理**：支持不同角色对配置后台的访问和操作权限控制

### 4. 边界与风险
- **功能边界**：
  - 不包含前端用户触达渠道（如APP推送、短信等）的具体实现
  - 不包含营销活动效果数据分析模块
  - 不涉及与第三方CRM/ERP系统的深度集成（仅考虑标准接口）
- **技术风险**：
  - 复杂的规则引擎可能导致配置逻辑难以理解和维护
  - 多维度组合条件可能带来性能挑战（如规则匹配效率）
- **业务风险**：
  - 门店分组和用户等级定义可能因业务变化频繁调整
  - 规则冲突检测的完备性影响投放准确性

### 5. MVP 建议
- **核心MVP功能**：
  1. 基础门店分组管理（支持手动添加门店）
  2. 简单用户等级配置（预设3-5个等级）
  3. 基本活动时间周期设置（开始时间、结束时间）
  4. 单一维度的投放规则配置（如仅按门店分组或仅按用户等级）
  5. 规则配置的保存和基础查看
- **优先级逻辑**：
  - 先支持单一维度规则，验证核心配置流程
  - 后续迭代增加多维度组合、规则冲突检测等高级功能

### 6. 给研发的实现提示
- **技术架构**：
  - 建议采用规则引擎（如Drools）或自定义规则表达式解析
  - 前端考虑使用可视化配置界面降低使用门槛
  - 数据库设计需考虑规则版本管理和历史记录
- **关键实现点**：
  - 规则配置与规则执行解耦，便于独立优化
  - 预留规则测试沙箱环境，支持配置人员自验证
  - 考虑规则生效时间的时区处理（尤其跨区域零售企业）
- **性能优化**：
  - 规则匹配考虑预编译和缓存机制
  - 大量门店分组时需注意查询性能优化
