# 产品需求分析：优惠券核销统计、日报导出与异常门店预警

## 1. 一句话总结
为优惠券投放后台系统增加核销数据统计、报表导出和异常门店监控功能模块，以提升运营数据可见性、分析效率及风险管控能力。

## 2. 核心用户问题
运营团队在优惠券管理过程中面临以下痛点：
- **数据可见性不足**：无法实时、直观地掌握各门店、各类型优惠券的核销情况和效果趋势
- **分析工具缺失**：缺乏便捷的数据导出功能，难以进行自定义深度分析或生成定期报告
- **风险感知滞后**：无法及时发现门店层面的异常核销行为（如异常高频核销、异常时段核销等），导致潜在风险无法及时干预
- **决策支持薄弱**：基于不完整或滞后的数据，难以制定精准的营销优化策略和资源调配决策

## 3. 关键功能点
### 3.1 核销数据统计看板
- **多维度数据聚合**：按门店、时间（日/周/月）、优惠券类型、用户群体等多维度聚合核销数据
- **核心指标展示**：
  - 总核销张数、总核销金额、核销率（核销数/投放数）
  - 各门店核销排名、各优惠券类型效果对比
  - 核销趋势图（日趋势、周趋势、月趋势）
- **交互式筛选与下钻**：支持按时间范围、门店类型、区域等条件筛选数据，并可下钻查看明细
- **实时/准实时更新**：支持近实时数据更新（如小时级延迟），确保数据时效性

### 3.2 报表导出功能
- **预设报表模板**：
  - **日报**：每日核销概况、门店Top10、异常预警摘要
  - **周报**：周度趋势分析、效果评估、下周建议
  - **月报**：月度总结、ROI分析、下月规划建议
- **自定义报表配置**：
  - 支持用户自定义数据维度、指标、筛选条件
  - 可保存自定义报表模板，方便定期生成
- **多格式导出**：
  - Excel（支持多Sheet、公式、图表）
  - PDF（格式化报告，适合邮件发送）
  - CSV（原始数据，适合进一步分析）
- **批量导出与定时发送**：
  - 支持批量生成多个报表
  - 可配置定时任务自动生成并发送至指定邮箱
  - 支持历史报表归档与查询

### 3.3 异常门店预警系统
- **预警规则配置**：
  - **阈值类规则**：单日核销量超过阈值、核销率异常偏高/偏低
  - **趋势类规则**：核销量环比/同比异常波动、非营业时段核销
  - **模式类规则**：同一用户短时间内多次核销、异常核销设备/IP集中
  - **组合规则**：多个条件的逻辑组合（如：新开门店+核销率异常高）
- **预警通知机制**：
  - 支持多级预警（提醒、警告、严重）
  - 多种通知渠道：系统内消息、邮件、企业微信/钉钉
  - 可按人员角色、区域配置不同的接收人
- **预警处理闭环**：
  - 预警列表与详情查看
  - 预警状态标记（待处理、处理中、已处理）
  - 处理记录与反馈录入
  - 预警有效性分析与规则优化
- **预警历史与分析**：
  - 历史预警记录查询与分析
  - 预警命中率、准确率统计
  - 规则效果评估与优化建议

## 4. 边界与风险
### 系统边界
- **数据源边界**：仅处理已发生的核销数据，不涉及优惠券生成、投放、财务结算等上游/下游流程
- **分析范围**：聚焦核销相关统计与预警，不扩展至用户行为分析、精准营销推荐等更广领域
- **预警执行**：仅负责异常检测与通知，不自动执行任何拦截、限制等管控操作
- **报表生成**：依赖现有核销数据结构和质量，不承诺修复上游数据问题

### 潜在风险
1. **数据质量风险**：核销数据记录不完整、不及时或存在错误，将直接影响统计准确性和预警有效性
2. **性能风险**：大范围、多维度数据聚合查询可能对数据库产生压力，影响系统响应速度
3. **预警误报风险**：初期预警规则可能不够精准，产生较多误报，影响用户体验和信任度
4. **规则维护成本**：随着业务变化，预警规则需要持续调整和优化，带来一定的维护成本
5. **数据安全风险**：核销数据包含商业敏感信息，导出功能可能增加数据泄露风险

## 5. MVP 建议
### 第一阶段（MVP核心功能）
1. **基础核销统计看板**：
   - 按日/门店维度的核销数据汇总
   - 核心指标展示（核销数、核销金额、核销率）
   - 简单趋势图展示
2. **基础日报导出**：
   - 固定格式的Excel日报导出
   - 包含核销概况和门店Top10数据
3. **简单阈值预警**：
   - 单日核销量超过固定阈值的预警
   - 系统内消息通知

### 第二阶段（功能增强）
1. **统计看板增强**：
   - 增加多维度筛选和下钻功能
   - 增加更多分析维度（优惠券类型、用户类型等）
2. **报表功能完善**：
   - 增加周报、月报模板
   - 支持PDF格式导出
3. **预警系统完善**：
   - 增加多种预警规则类型
   - 支持邮件和企业微信通知
   - 预警处理状态跟踪

### 第三阶段（高级功能）
1. **自定义报表**：支持用户完全自定义报表配置
2. **智能预警**：基于机器学习模型的异常检测
3. **定时任务与自动化**：完整的报表自动生成与分发体系

## 6. 给研发的实现提示
### 架构设计建议
1. **分层数据架构**：
   - **原始数据层**：保持核销原始记录，便于溯源
   - **聚合数据层**：建立预聚合的统计表，提升查询性能
   - **缓存层**：对高频访问的统计数据使用Redis缓存
2. **异步处理机制**：
   - 报表生成等耗时操作采用消息队列异步处理
   - 预警规则计算可采用定时批处理或流式处理，根据实时性要求选择
3. **微服务划分**：
   - 可将统计服务、报表服务、预警服务拆分为独立微服务，便于独立扩展

### 技术实现要点
1. **数据聚合策略**：
   - 对于实时性要求高的数据，采用流处理（如Flink/Kafka Streams）
   - 对于批量分析，可采用定时ETL任务预计算
   - 考虑使用列式存储（如ClickHouse）处理大规模聚合查询
2. **报表生成技术**：
   - Excel导出推荐使用Apache POI或EasyExcel（避免OOM）
   - PDF生成可使用iText或Apache PDFBox
   - 考虑支持HTML转PDF方案，便于样式控制
3. **预警规则引擎**：
   - 规则配置建议采用DSL（领域特定语言）或可视化配置
   - 规则引擎可考虑使用Drools等开源方案，或自研轻量引擎
   - 注意规则的热加载能力，避免频繁重启服务
4. **性能优化**：
   - 对统计查询建立合适的数据库索引
   - 对大表查询考虑分库分表策略
   - 报表生成考虑增量生成和结果缓存

### 数据安全考虑
1. **数据权限控制**：确保用户只能查看和导出其权限范围内的数据
2. **导出限制**：对大范围数据导出设置行数限制或审批流程
3. **敏感信息脱敏**：导出数据中对敏感信息进行脱敏处理
4. **操作审计**：记录所有数据导出和预警操作，便于审计追踪

### 集成注意事项
1. **数据同步一致性**：与核销系统保持数据同步的一致性策略
2. **通知渠道集成**：与企业微信、钉钉等IM工具的良好集成
3. **监控与告警**：对报表生成、预警计算等关键任务建立监控告警机制
