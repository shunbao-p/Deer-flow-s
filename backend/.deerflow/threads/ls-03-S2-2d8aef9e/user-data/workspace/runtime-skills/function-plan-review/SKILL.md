# 功能方案评审技能

## 触发条件
当用户提供功能方案草稿文本并要求按固定流程评审时立即使用本技能。

## 输入
- 功能方案草稿文本（通常由用户提供）

## 输出
结构化评审报告，包含以下六个固定部分：
1. 需求摘要
2. 用户价值  
3. 功能拆解
4. 实施风险
5. MVP范围
6. 给研发的落地建议

## 工作流程

### 第一步：理解功能方案
仔细阅读用户提供的功能方案草稿文本，理解核心需求、目标用户和业务场景。

### 第二步：生成评审报告
按照固定模板生成结构化评审报告：

#### 1. 需求摘要
- 用一句话总结核心需求
- 明确解决的主要问题
- 定义基本业务目标

#### 2. 用户价值
- 分析对终端用户的实际价值
- 识别核心用户群体
- 评估价值实现路径

#### 3. 功能拆解
- 详细分解功能模块
- 列出具体子功能点
- 明确功能间依赖关系
- 建议技术实现方案

#### 4. 实施风险
- 识别技术风险（架构、性能、安全等）
- 识别业务风险（需求变更、用户接受度等）
- 识别实施风险（资源、时间、依赖等）
- 提出风险缓解建议

#### 5. MVP范围
- 建议最小可行产品范围
- 确定核心功能优先级
- 定义MVP验收标准
- 建议迭代规划

#### 6. 给研发的落地建议
- 提供具体技术实施建议
- 建议技术选型和架构
- 提醒关键实现难点
- 建议开发优先级和排期

### 第三步：输出评审报告
以清晰的结构化格式呈现评审报告，使用Markdown格式，确保每个部分都有详细的分析和建议。

## 质量要求
- 评审报告应基于功能方案草稿的实际内容
- 每个部分的分析应具体、可操作
- 建议应切实可行，考虑实际实施条件
- 保持客观、专业的评审态度

**输入示例：**

### 1. 需求摘要
一句话总结：建设会员积分商城系统，实现积分兑换商品、库存管理和订单跟踪功能。
