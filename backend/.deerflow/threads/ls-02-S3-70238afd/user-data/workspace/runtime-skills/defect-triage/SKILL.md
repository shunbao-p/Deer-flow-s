# 缺陷分诊技能

当用户提供缺陷描述并要求按固定缺陷分诊流程分析时，立即使用本技能。

## 工作流程

1. **接收缺陷描述**：获取用户提供的缺陷描述文本
2. **分析缺陷内容**：理解缺陷的核心问题、发生场景和潜在影响
3. **生成结构化分析**：按照以下6个固定部分输出分析结果：
   - **问题摘要**：用一两句话概括缺陷的核心问题
   - **影响范围**：分析缺陷影响哪些用户、哪些功能、哪些场景
   - **可能原因**：列出可能的技术原因或业务逻辑问题
   - **建议优先级**：根据影响范围和严重程度给出优先级建议（P0/P1/P2/P3）
   - **建议排查步骤**：提供具体的排查方向和步骤建议
   - **是否需要立即升级**：判断是否需要立即上报或升级处理（是/否）
4. **返回分析结果**：以清晰的结构化格式呈现分析结果

## 输出格式

每次分析必须严格按照以下模板输出：

```
## 缺陷分诊分析

### 1. 问题摘要
[用一两句话概括缺陷的核心问题]

### 2. 影响范围
- 影响用户：[描述影响的用户群体]
- 影响功能：[描述影响的功能模块]
- 影响场景：[描述影响的业务场景]

### 3. 可能原因
1. [可能原因一]
2. [可能原因二]
3. [可能原因三]

### 4. 建议优先级
[P0/P1/P2/P3] - [优先级说明]

### 5. 建议排查步骤
1. [排查步骤一]
2. [排查步骤二]
3. [排查步骤三]

### 6. 是否需要立即升级
[是/否] - [升级建议说明]
```

## 注意事项

- 保持分析客观、基于事实
- 优先级判断应综合考虑影响范围和严重程度
- 排查步骤应具体、可操作
- 升级判断应基于缺陷的紧急性和业务影响
- 确保每次分析都使用相同的结构，便于后续跟踪和处理
